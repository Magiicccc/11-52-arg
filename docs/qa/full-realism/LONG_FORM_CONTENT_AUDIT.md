# 长正文完整性审计

审计日期：2026-07-29

审计范围：知乎、今日头条、小红书、百度贴吧的普通生活内容

分支：`fix/github-pages-ui-realism`

## 判定规则

- 列表摘要只负责帮助用户判断是否打开，不得代替详情正文。
- 知乎回答需要形成明确的问题界定、方法展开、例子或边界说明、结论。
- 今日头条文章需要有独立导语、信息来源、连续报道正文和收束段。
- 小红书笔记需要有具体场景、过程、个人判断和可独立读完的结尾。
- 百度贴吧发帖允许以问题结束，但必须完整说明背景、具体经过、已尝试方法和明确问题。
- 普通内容必须保留 `NarrativeMetadata`；冻结剧情内容、正式台词和线索文本不因本次审计而改写。
- 段落不得以逗号、顿号或冒号截断，不得用“待补”“草稿未完”冒充已发布正文。

## 本轮修复

- 删除 `ZhihuApp` 内未参与运行时数据投影的十条两段式旧样例，避免未来误接回页面。
- 将 16 条贴吧普通帖子从“两句提纲”重写为四段完整发帖。
- 保持贴吧原有标题、作者、时间、吧名、回复、媒体引用和 `NarrativeMetadata` 不变。
- 新增自动化门禁，检查贴吧正文数量、段落数、最低长度、句末闭合、段落去重、回复数量和叙事元数据。
- 继续使用已有门禁检查知乎、头条和小红书的正文长度与段落结构。

## 详情页验证

- 知乎详情默认显示前三段，点击“展开全文”后显示六段完整回答。
- 今日头条详情显示导语与四段正文。
- 小红书详情直接显示四段正文与对应评论。
- 贴吧详情显示四段楼主正文，列表只显示第一段作为预览。
- Playwright 已验证 402×874 下知乎、头条、贴吧详情正文和页面交互；测试结果为 8/8 通过。

## 保留边界

正式剧情内容可能因权威内容圣经的冻结文本而短于普通长正文标准。本轮没有将其扩写、润色或与普通文章合并。若正式条目在页面中需要更高阅读密度，应通过同页普通内容、真实导航和评论结构改善，而不是擅自续写正式剧情。
